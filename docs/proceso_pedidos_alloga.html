Proceso de Pedidos Alloga (EcoVital)

BORRADOR — pendiente de validar   Autor: Marc Eslava  ·  Última actualización: 24/07/2026

Este documento describe, de principio a fin, cómo se procesan los pedidos de la tienda online EcoVital hasta que llegan a Alloga, qué componentes intervienen, cuándo se ejecuta cada parte y qué hacer cuando hay problemas. El objetivo es que cualquier miembro del equipo pueda operar y desatascar el proceso sin depender de una sola persona.

1. Resumen del proceso

Un cliente hace un pedido en la tienda online EcoVital (plataforma LogiCommerce). Cada día, un proceso automático (Airflow) recoge los pedidos nuevos, los completa con los datos del cliente y de la farmacia, y genera un fichero por pedido. Un bot (Aqua BPI) recoge esos ficheros y los introduce en Alloga (el operador logístico que prepara y envía la mercancía). Por último, el pedido se marca como "en proceso" en LogiCommerce.

PiezaRol
LogiCommerceTienda online EcoVital — origen de los pedidos y de los clientes.
API EcoceuticsAporta el FID del cliente a partir del NIF.
BD fidfarma (vía túnel SSH)Aporta el código de cliente Alliance (id_unit_izaro) de cada farmacia.
AirflowOrquesta la extracción, el cruce de datos y la subida de ficheros al FTP.
FTP de AquaBuzón donde se dejan los ficheros de pedido (Pedidos_AP_{nº}.csv).
Bot Aqua BPIRecoge los ficheros del FTP y los tramita hacia Alloga.
AllogaOperador logístico — destino final del pedido.

4. Paso a paso del pipeline ecovital_etl

1
generate_token
Genera el token de autenticación para la API de LogiCommerce.
2
extract_orders / extract_users
Descarga todos los pedidos y todos los usuarios/clientes de LogiCommerce (paginado).
3
transform_orders → extract_order_details
Obtiene los nº de pedido y, por cada uno, descarga el detalle: producto (SKU), unidades, precio, descuento, impuestos, RE y NIF.
4
extract_nif_data
Por cada NIF, consulta la API de Ecoceutics para obtener el FID del cliente.
5
transform_users
Normaliza las direcciones de facturación de los clientes.
6
alliance_clients
Vía túnel SSH, consulta la BD fidfarma (tabla Unit, bt_status=1) para obtener el código de cliente Alliance de cada farmacia por NIF.
7
load_fact_table
Cruza todo y construye la tabla final: Nº Pedido, Código Farmacia, Código Producto, Unidades, Precio, Descuento, Fecha Pedido.
8
cleanup_ftp
Lee el FTP, calcula el nº de pedido máximo ya subido y borra los ficheros Pedidos_AP_*.csv antiguos.
9
upload_to_ftp
Sube un CSV por pedido (Pedidos_AP_{nº}.csv), solo los pedidos nuevos (nº mayor que el máximo anterior).
10
execute_bot
Dispara el bot de Aqua BPI, que recoge los ficheros y los tramita hacia Alloga.
11
change_state_logicommerce
Marca cada pedido subido como "en proceso" (estado 2) en LogiCommerce.
Idea clave (anti-duplicados): el proceso solo sube pedidos con número mayor que el máximo que ya estaba en el FTP. Por eso, si se borra o manipula el FTP a mano, se puede alterar qué pedidos se consideran "nuevos".

6. Paso manual

⚙️ Paso manual — Ejecutar la query update_pedidos en Aqua

Dentro del proceso hay un paso que se realiza a mano en la aplicación de escritorio Aqua: lanzar una consulta SQL (update_pedidos) con una fecha concreta.

  • Cuándo: cuando lo indique Silvia — ella facilita la fecha que hay que introducir.
  • Herramienta: aplicación de escritorio Aqua (ventana 01-26 / Hygie31 España SLU).
  • Credenciales: usuario jubach. La contraseña está en el gestor de contraseñas del equipo (entrada «Login credentials»); no se escribe aquí por seguridad.

Pasos

  1. Abrir Aqua e iniciar sesión con el usuario/contraseña indicados captura 1.
  2. Ir a Menú → Instrucciones SQL captura 2.
  3. Abrir y seleccionar la consulta update_pedidos captura 3.
  4. Introducir en la query la fecha que indique Silvia.
  5. Con la query seleccionada, pulsar Ejecutar.

Cómo comprobar que salió bien: la verificación la realiza Silvia desde su propio sistema — no la hace quien ejecuta la query.

7. Resolución de problemas

Síntomas frecuentes, dónde mirar y qué hacer. Marc: revisar/añadir las acciones manuales reales.

SíntomaCausa probableDónde mirar / qué hacer
El pipeline no sube ningún pedido ("No new pedidos to upload") No hay pedidos nuevos, o el nº máximo del FTP quedó por encima de lo esperado. Revisar el FTP (aqua_ftp) y el log de cleanup_ftp (nº máximo detectado).
Un pedido concreto no llega a Alloga No se generó/subió su fichero, o el bot no lo tramitó. Comprobar que existe Pedidos_AP_{nº}.csv en el FTP; revisar log de upload_to_ftp y el portal de Aqua BPI.
Falta el Código Farmacia en el fichero Túnel SSH caído, o el NIF no tiene equivalencia en la tabla Unit (bt_status=1). Revisar log de alliance_clients ("SSH tunnel unavailable…" / "No matching units"). Verificar el túnel ssh_tunnel y la BD fidfarma_db.
En el log aparece NIF … SKIP La API de Ecoceutics devolvió error para ese NIF (cliente sin FID). Es esperable para clientes sin ficha; si son muchos, revisar la API de Ecoceutics.
execute_bot falla El portal de Aqua BPI no responde, o cambiaron credenciales/IDs del bot. Revisar el log de execute_bot y el estado del portal Aqua BPI (instancia b71ccef7…).
change_state_logicommerce falla con TLG014130 El pedido ya estaba "en proceso". No es un error real — el proceso lo ignora automáticamente.
LogiCommerce no autentica (401 / token) logicommerce_secret o logicommerce_app_id incorrectos/caducados. Revisar las Variables de Airflow y regenerar credenciales en LogiCommerce si procede.
Pedidos duplicados en Alloga Se re-subieron ficheros ya procesados (p. ej. tras tocar el FTP a mano). Confirmar el nº máximo en el FTP antes de re-ejecutar; no borrar ficheros sin entender el efecto en el control anti-duplicados.
Los pedidos salen con una fecha incorrecta / Silvia pide corregir la fecha Hay que forzar la fecha manualmente en origen. Ejecutar la query update_pedidos en Aqua con la fecha que indique Silvia — ver §6 Paso manual.
